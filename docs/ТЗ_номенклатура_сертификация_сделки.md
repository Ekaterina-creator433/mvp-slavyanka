# Техническое задание
## Модули «Номенклатура», «Сертификация», «Сделки», «Материалы», «ОТК», «Задачи»
### MVP SaaS-платформы швейного предприятия ООО «Славянка Текстиль»

---

## 1. Общие сведения

- **Объект автоматизации:** швейное предприятие ООО «Славянка Текстиль» — малосерийное и серийное производство специальной одежды (костюмы, полукомбинезоны, куртки).
- **Наименование:** модули управления номенклатурой, сертификацией и сделками MVP SaaS-платформы предприятия.
- **Заказчик:** ООО «Славянка Текстиль».
- **Назначение:** замена разрозненных таблиц и бумажных журналов единой веб-системой; связывание выпускаемой продукции с сертификатами и продажами в одном контуре.
- **Версия документа:** 1.0

## 2. Цели создания

1. Вести каталог продукции в одном месте вместо Excel-файлов разных отделов.
2. Исключить пропуск окончания срока действия сертификатов за счёт автоматического контроля.
3. Сократить время подготовки коммерческих предложений за счёт генерации документа из данных сделки.

## 3. Термины и сокращения

| Термин | Значение |
|---|---|
| Номенклатура | Каталог выпускаемых изделий со всеми атрибутами |
| Сертификат | Документ соответствия (ТР ТС, ГОСТ), подтверждающий безопасность изделия |
| Сделка | Процесс продажи: от заявки до коммерческого предложения, с позициями и суммой |
| КП | Коммерческое предложение — документ с составом и стоимостью поставки |
| Партия | Количество единиц одного изделия, поступившее на контроль качества |
| Брак | Изделия партии, не прошедшие контроль качества |
| ТУ | Технические условия на изделие |
| ТР ТС | Технический регламент Таможенного союза |

## 4. Функциональные требования

### 4.1. Модуль «Номенклатура»

**Назначение:** ведение каталога выпускаемой спецодежды.

Требуется обеспечить:

1. Создание, редактирование, удаление карточек изделий (CRUD).
2. Атрибуты карточки изделия:
   - наименование, артикул;
   - тип изделия (костюм, полукомбинезон, куртка и т.д.);
   - класс защиты: огнестойкая, антистатическая, защита от нефти/нефтепродуктов, энцефалитная;
   - климатический пояс;
   - материал / состав ткани;
   - размерный ряд и роста;
   - коды ТН ВЭД и ОКПД2;
   - номер и наименование ТУ;
   - цена за единицу.
3. Автозаполнение кодов (ТН ВЭД, ОКПД2, ТУ) по выбранному типу изделия — пресеты.
4. Автоматическую привязку действующих сертификатов к новому изделию по совпадению типа защиты.
5. Поиск и фильтрацию по наименованию, типу, классу защиты.
6. Просмотр в карточке изделия связанных объектов: сертификаты, записи реестра промышленной продукции.

### 4.2. Модуль «Сертификация»

**Назначение:** реестр сертификатов и контроль их сроков.

Требуется обеспечить:

1. Ведение реестра сертификатов со следующими полями:
   - регистрационный номер;
   - вид документа (сертификат / декларация соответствия, ТР ТС 019/2011, ГОСТ);
   - привязка к изделию или типу защиты;
   - орган, выдавший документ;
   - дата начала и дата окончания действия;
   - статус: действует / истекает / истёк.
2. Автоматический расчёт статуса по текущей дате.
3. Предупреждение об окончании срока за **30 дней**:
   - подсветка в реестре и на дашборде;
   - создание задачи ответственному;
   - уведомление в Telegram (опционально, при отсутствии токена — лог в консоль).
4. Отчёт по сертификатам: всего, действующих, истекающих, просроченных.

### 4.3. Модуль «Сделки»

**Назначение:** учёт продаж от заявки до выдачи коммерческого предложения.

Требуется обеспечить:

1. Справочник контрагентов: наименование, ИНН, контактные данные, реквизиты.
2. Создание сделки с обязательной привязкой к контрагенту.
3. Этапы сделки: заявка → подготовка КП → КП отправлено → согласовано / отказ (изменение статуса вручную).
4. Позиции сделки:
   - выбор товара из номенклатуры;
   - количество и цена;
   - автоматический расчёт суммы позиции и итога сделки.
5. Генерацию коммерческого предложения из шаблона по данным сделки (реквизиты сторон, позиции, суммы).
6. Комментарии к сделке, история изменения этапа.
7. Отчёт по продажам: суммы за период, топ контрагентов.

### 4.4. Модуль «Материалы»

**Назначение:** справочник материалов и учёт снабжения производства.

Требуется обеспечить:

1. Ведение справочника материалов: наименование, поставщик, единица измерения, цена, остаток.
2. Привязку материалов к изделиям номенклатуры (состав изделия).
3. Создание, редактирование, удаление материалов (CRUD), поиск.
4. Импорт/экспорт справочника.

### 4.5. Модуль «ОТК · Контроль качества»

**Назначение:** контроль качества партий готовой продукции.

Требуется обеспечить:

1. Регистрацию партий: изделие из номенклатуры, количество, дата поступления.
2. Статусы проверки партии: ожидает проверки / принята / брак.
3. Учёт брака: количество забракованных единиц и причина.
4. Автоматическое создание задачи ОТК при регистрации партии.
5. Отчёт по качеству: доля принятых партий, объём брака по причинам.

### 4.6. Модуль «Задачи»

**Назначение:** поручения сотрудников по объектам системы.

Требуется обеспечить:

1. Создание задач с полями: заголовок, исполнитель (роль), срок, статус (открыта / выполнена).
2. Привязку задачи к объекту: изделие, сертификат, партия, сделка — выбор объекта из списка, а не ввод ID вручную.
3. Автосоздание задач по контролю сроков сертификатов и проверке партий ОТК.
4. Фильтрацию задач по исполнителю, статусу и сроку.

### 4.7. Сквозные требования

- Импорт/экспорт данных модулей в форматах CSV, XLSX, JSON.
- Все события по срокам отражаются на дашборде руководителя.

## 5. Роли пользователей

| Роль | Действия в модулях |
|---|---|
| Менеджер по продажам | Каталог (просмотр), сделки, КП |
| Технолог | Номенклатура, материалы, ТУ |
| Снабженец | Материалы, поставщики, закупки |
| ОТК | Партии, статусы проверок, учёт брака |
| Руководитель | Отчёты, уведомления о критичных событиях |

## 6. Нефункциональные требования

1. Веб-интерфейс, доступ через браузер без установки ПО (порт 4000).
2. Стек: Node.js ≥ 22 + Express, SQLite (встроенный `node:sqlite`, без внешней БД), фронтенд — HTML/CSS/JS без сборщиков.
3. Русскоязычный интерфейс.
4. База данных — один файл `data/slavyanka.db` (резервное копирование копированием файла).
5. Уведомления Telegram — опционально, настройка через `.env`.

## 7. Критерии приёмки

1. Создание изделия по пресету заполняет коды автоматически; сертификат подходящего типа привязывается сам.
2. При добавлении сертификата со сроком менее 30 дней система помечает его «истекает» и создаёт уведомление.
3. Сделка с двумя позициями считает сумму корректно; из неё выгружается КП с фактическими данными сделки.
4. Экспорт номенклатуры в XLSX открывается в Excel без искажений.
5. Партия с браком отражается в отчёте качества с указанием причины.

## 8. Этапы работ

1. Схема БД: products, certificates, contractors, deals, deal_items, documents, materials, quality_batches, tasks.
2. API модулей (REST, JSON).
3. Интерфейс: вкладки «Номенклатура», «Сертификаты», «Сделки», «Материалы», «ОТК», «Задачи».
4. Контроль сроков сертификатов и уведомления.
5. Генерация КП, импорт/экспорт, отчёты.
