# Скилл работы с репозиторием mvp-slavyanka

MVP SaaS-платформа для производителя спецодежды ООО «Славянка Текстиль»:
номенклатура, сертификаты, сделки, ОТК, задачи, импорт/экспорт, отчёты.

## 1. Структура репозитория

```
mvp-slavyanka/
├── server.js          # Express-сервер: все API-роуты и логика
├── db.js              # Схема и инициализация SQLite (node:sqlite)
├── package.json       # Зависимости и скрипты (start, dev)
├── public/            # Фронтенд без сборщиков
│   ├── index.html     # Каркас интерфейса и навигация (data-view)
│   ├── app.js         # Логика: views-объект, hash-роутер (#/products и т.д.)
│   └── style.css      # Стили
├── data/              # SQLite-база (slavyanka.db) — в git НЕ входит
├── .env.example       # Шаблон переменных окружения (Telegram)
└── README.md          # Описание проекта
```

Ключевые факты: Node.js >= 22 (используется встроенный `node:sqlite`),
порт **4000**, фронтенд — чистый HTML/CSS/JS, роутинг по `location.hash`.
Разделы: дашборд, номенклатура, сертификаты, реестр Минпромторга (МПТ),
сделки, ОТК, материалы, задачи, контрагенты, импорт/экспорт, отчёты.
Контроль сроков: сертификаты — предупреждение за 30 дней (`CERT_WARN_DAYS`),
реестровые записи МПТ — за 8 месяцев / 240 дней (`MP_WARN_DAYS` в `server.js`).

## 2. Запуск сервиса

```bash
npm install
npm start        # http://localhost:4000
```

Проверка, что сервис поднялся:

```bash
curl http://localhost:4000/api/products
curl http://localhost:4000/api/certificates
```

## 3. Внесение изменений

- **API и бизнес-логика** — добавляй роуты в `server.js`, следуя существующему
  стилю (Express-роуты, ответы в формате JSON).
- **Таблицы БД** — меняй схему в `db.js`; при миграциях учитывай, что файл базы
  в `data/` у пользователей уже существует.
- **Фронтенд** — новая вкладка = новый `views.<имя>` в `public/app.js` +
  ссылка `<a data-view="...">` в `public/index.html`. Роутер читает hash
  при загрузке и на `hashchange`.
- Не добавляй сборщики и тяжёлые зависимости — принцип проекта «без билда».

## 4. Обновление README.md

Структура README: название → проблема → пользователи → возможности → стек →
запуск → Telegram → проверка API. При изменении функциональности обновляй
раздел «Возможности» и команды проверки. Пиши кратко, по-русски.

## 5. Проверка ошибок

```bash
node --check server.js     # синтаксис
node --check db.js
npm audit                  # уязвимости зависимостей
```

Функциональная проверка после изменений: запустить сервер и прогнать основные
эндпоинты из раздела «Проверка API» в README.

## 6. Подготовка к публикации

1. Убедись, что в git не попадают: `.env`, `data/*.db*`, `*.log`, `*.pid`,
   `node_modules/` (все уже в `.gitignore`).
2. `git status` — только ожидаемые файлы.
3. Коммиты: короткое сообщение на английском в императиве
   («Add UI screenshots», «Fix certificate expiry check»).
4. Пуш в `origin main`: `git push origin main`.
5. Репозиторий: github.com/Ekaterina-creator433/mvp-slavyanka
